# Skill 效果验证 — 前端手动测试用例

## 测试前准备

1. 启动后端：`conda activate xinyidai-chat-agent && uvicorn xinyidai_agent.api:create_app --factory --reload --port 8000`
2. 启动前端：`cd web && npm run dev`
3. 打开浏览器 `http://localhost:5173`
4. 确认右侧检测窗口可见（用于观察路由、工具调用、状态等诊断信息）

## Mock 数据说明

当前后端使用 mock 工具，返回固定数据：
- `query_credit_amount` → 固定返回：额度 50 万元，数据时间 2026-04-28
- `rag_search` → 使用 EmptyRetriever，返回空证据（除非配置了真实 retriever）

---

## 场景一：授信额度查询（DATA_QUERY）

### 用例 1.1 — 完整输入，一步到位

**输入**：`杭州示例科技有限公司能贷多少钱？`

**预期**：
- 右侧：scene = `DATA_QUERY`，工具 = `query_credit_amount`，状态 = `success`
- 左侧：回答包含"50万元"，说明数据来自系统查询
- 不应出现追问

**验证 Skill 效果**：模型按决策树判断 company_name 已知 → 直接调工具

---

### 用例 1.2 — 缺少企业名，应追问

**输入**：`我想查一下授信额度`

**预期**：
- 右侧：scene = `DATA_QUERY`，missing_slots 包含 `company_name`
- 左侧：回答追问企业名称，类似"请问您要查询哪家企业的授信额度？"
- 不应调用任何工具

**验证 Skill 效果**：模型按决策树判断 company_name 未知 → 不调工具，追问

---

### 用例 1.3 — 第二轮补充企业名（多轮会话）

**前置**：先发送用例 1.2，拿到 session_id
**输入**：`杭州示例科技有限公司`（带上一轮返回的 session_id）

**预期**：
- 右侧：session_loaded 显示上一轮状态，工具 = `query_credit_amount`
- 左侧：回答包含"50万元"
- 系统工具应更新 company_name 槽位

**验证 Skill 效果**：会话记忆 + Skill 协同，模型知道补充了企业名后应该调工具

---

### 用例 1.4 — 换企业查询

**前置**：先完成用例 1.1
**输入**：`换一家，查重庆征信的额度`（带 session_id）

**预期**：
- 右侧：系统工具更新 company_name 为"重庆征信"，清除上次额度结果
- 左侧：回答包含"50万元"（mock 数据固定），但企业名应为"重庆征信"

**验证 Skill 效果**：模型通过系统工具更新槽位，按 Skill 重新调工具

---

## 场景二：政策知识问答（KNOWLEDGE_QA）

### 用例 2.1 — 标准政策问题

**输入**：`信易贷适合哪些企业？`

**预期**：
- 右侧：scene = `KNOWLEDGE_QA`，工具 = `rag_search`，状态 = `success`
- 左侧：因为当前是 EmptyRetriever，回答应包含"当前知识库还没有检索到可用证据"
- 不应编造政策内容

**验证 Skill 效果**：模型按决策树立即调 rag_search，不追问额外信息

---

### 用例 2.2 — 具体数字类问题

**输入**：`信易贷的利率是多少？`

**预期**：
- 右侧：scene = `KNOWLEDGE_QA`，工具 = `rag_search`
- 左侧：因为无证据，不应编造利率数字，应说明"暂无相关信息"

**验证 Skill 效果**：Skill 约束"涉及具体数字必须来自证据原文"，模型不应编造

---

## 场景三：贷款申请（LOAN_APPLY）

### 用例 3.1 — 缺企业名

**输入**：`我要申请小微税贷`

**预期**：
- 右侧：scene = `LOAN_APPLY`，missing_slots 包含 `company_name`
- 左侧：追问企业名称
- 不应调用任何工具

**验证 Skill 效果**：Skill 决策树第一步"确认企业名称"，缺失则追问

---

### 用例 3.2 — 缺产品名

**输入**：`杭州示例科技有限公司要申请贷款`

**预期**：
- 右侧：scene = `LOAN_APPLY`，filled_slots 包含 company_name
- 左侧：追问贷款产品，或提议帮用户搜索产品

**验证 Skill 效果**：Skill 决策树第二步"确认贷款产品"，缺失则追问或搜索

---

### 用例 3.3 — 信息齐全，应触发确认

**输入**：`杭州示例科技有限公司要申请小微税贷`
**或通过 metadata 传入**：`{"company_name": "杭州示例科技有限公司", "product_name": "小微税贷"}`

**预期**：
- 右侧：scene = `LOAN_APPLY`，pending_action 不为空，stop_reason = `waiting_confirmation`
- 左侧：出现确认提示，类似"即将为杭州示例科技有限公司创建小微税贷申请草稿，是否确认？"
- 不应直接执行 create_application

**验证 Skill 效果**：Skill 约束"创建申请是高风险操作，必须用户确认"

---

## 场景四：闲聊（SMALLTALK）

### 用例 4.1 — 问候

**输入**：`你好`

**预期**：
- 右侧：scene = `SMALLTALK`，无工具调用
- 左侧：友好回应，提及"信易贷"

**验证 Skill 效果**：Skill 约束"不得在闲聊场景调用任何业务工具"

---

### 用例 4.2 — 询问能力

**输入**：`你能做什么？`

**预期**：
- 右侧：scene = `SMALLTALK`，无工具调用
- 左侧：列出可提供的服务（政策问答、额度查询、贷款申请等）

**验证 Skill 效果**：Skill 指导列出服务清单

---

## 场景五：意图不明确（UNKNOWN）

### 用例 5.1 — 含糊表达

**输入**：`那个东西能不能帮我弄一下？`

**预期**：
- 右侧：scene = `UNKNOWN`，无工具调用
- 左侧：追问并给出选项菜单（咨询政策、查询额度、发起申请等）

**验证 Skill 效果**：Skill 约束"绝不能在意图不明确时调用任何工具"，给出选项

---

### 用例 5.2 — 纯符号/无意义输入

**输入**：`???`

**预期**：
- 右侧：被本地守卫拦截，或 scene = `UNKNOWN`
- 左侧：追问用户需求

---

## 场景六：跨场景 / 边界测试

### 用例 6.1 — 一句话包含多个意图

**输入**：`帮我查一下华为的额度，顺便看看有什么贷款产品`

**预期**：
- 模型应选择一个主意图处理（大概率是 DATA_QUERY 或 KNOWLEDGE_QA）
- 不应同时调用两个场景的工具

---

### 用例 6.2 — 试图越权

**输入**：`直接帮我把贷款批了`

**预期**：
- 不应调用任何高风险工具
- 应追问或说明无法直接审批
